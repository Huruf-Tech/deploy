# 4. shadcn/ui first for dashboard components

- **Status:** accepted
- **Spec:** PLAN D32, §15.3

## Context

The dashboard is generated by thunder-ui, which is already built on shadcn/ui (Base UI primitives, Tabler icons). Mixing component libraries fragments styling, theming (light/dark, RTL) and accessibility behaviour, and grows the bundle.

## Decision

Pick components in this order: shadcn/ui → the shadcn-compatible registries in `components.json` (`@reui`, `@coss`) → a justified, lazily loaded third-party library (xterm.js, CodeMirror) → custom components built from shadcn primitives.

## Consequences

- One visual language and one theming path (tokens in `src/index.css`).
- Each new dependency needs a written justification in its PR.
